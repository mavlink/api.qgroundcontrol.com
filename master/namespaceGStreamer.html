Detailed Description

Scoped owners for transfer-full GStreamer returns so refs can't leak on early return. Use the adopt* helpers at the transfer-full call boundary; .get() yields a non-owning view. Floating refs (e.g. gst_element_factory_make) are consumed by gst_bin_add/gst_element_add_pad even when the call fails, so release() the owner into the call, or sink them at creation with makeElement() or adoptFloating().

◆ avoidHevcWavefrontDeadlock()

bool GStreamer::avoidHevcWavefrontDeadlock ( GstElement * decoder,
QLatin1StringView version = libavcodecVersion() )

FFmpeg defect, in FFmpeg 7.1.0 (libavcodec 61.19.100), which GStreamer's 1.28 packages for Android, iOS, macOS and Windows carry: it decodes the wavefront rows of an HEVC picture on slice threads that wait for one another through condition variables indexed by thread, not by row. With more rows than threads a row can wait forever, and avdec_h265's streaming thread with it, so that the decoder can be neither stopped nor replaced. FFmpeg 7.1.1 has the fix, and this can go once no package QGC builds with has 7.1.0. libav decodes on slice threads behind a live source, and where decodeWithoutDelay() asks for them. With that version this has decoder, when it is avdec_h265, decode on one thread, which takes the rows in order. Returns whether it changed the decoder.

◆ countRtpPackets()

bool GStreamer::countRtpPackets ( GstElement * bin,
GstPad * pad,
int clockRate )

Counts the RTP packets pad pushes from now on with an RtpPacketCounter, as bin's: for a source without a jitter buffer, which nothing else counts. clockRate: of their timestamps, in Hz. False when the pad takes no probe.

The probe runs on the pad's streaming thread for every packet, in buffers and buffer lists alike: it reads the fixed header of each packet that is RTP version 2 and not an RTCP packet sent to the same port, takes the buffer's DTS (else PTS) as its arrival time, as a jitter buffer does, and neither allocates nor logs. The totals are handed over in atomics.

◆ serializeUdpSrcUnlock()

void GStreamer::serializeUdpSrcUnlock ( )

GStreamer defect, fixed in gst-plugins-good 1.24.10: udpsrc's unlock_stop() replaces its GCancellable on the streaming thread (basesrc defers it to the first create() after PLAYING) while unlock() cancels it from the thread leaving PLAYING. A pipeline stopped right after it started then cancels a freed GCancellable and corrupts the heap. On the versions before that one this wraps the two udpsrc class methods to serialize them, as the upstream fix does (gstreamer!7897); on newer ones, or without udpsrc, it does nothing. Runs once per process, after gst_init().
