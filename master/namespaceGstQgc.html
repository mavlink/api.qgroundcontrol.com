Detailed Description

GstVideoSink that pushes decoded frames into a Qt QVideoSink; sole sink in qgcvideosinkbin. Streaming-thread vfuncs MUST NOT touch QObject members directly (thread-affinity asserts) — hand off via QMetaObject::invokeMethod / bus messages.

◆ GpuBinMode

enum class GstQgc::GpuBinMode
strong

Head of qgcvideosinkbin's GPU branch. Linux builds with both gst-gl and DMABuf compile GlUpload and DirectDmaBuf; every other build compiles exactly one.

Enumerator
Passthrough 

Every compiled native memory straight into qgcqvideosink (Windows, Apple, ...).

GlUpload 

glupload → glcolorconvert → GLMemory 2D; gst-gl imports LINEAR and vendor-tiled DMABuf.

DirectDmaBuf 

memory:DMABuf and DMA_DRM into QGC's own importer (LINEAR only), skipping gst-gl's copy.

◆ buildSinkCaps()

std::string GstQgc::buildSinkCaps ( const SinkCapsPolicy &  policy)

The caps qgcqvideosink accepts under policy, most preferred first, all in the Qt-renderable formats of kVideoFormatTable. The glupload variant takes GLMemory only, as glcolorconvert outputs it. Otherwise, with gpu-zerocopy, the GPU memory policy's render target imports comes first: EGL-importable DMA_DRM and DMABuf on OpenGL over EGL while the DMABuf import works; GLMemory, unless the direct DMABuf variant, wherever gst-gl shares Qt's OpenGL context (EGL or GLX); AHardwareBuffer on OpenGL over EGL (Android); D3D11Memory on Direct3D11; none elsewhere. GLMemory always carries texture-target=2D, the only target the GL path samples. System memory always closes the list. DMABuf builds query EGL for importable DMA_DRM modifiers.
