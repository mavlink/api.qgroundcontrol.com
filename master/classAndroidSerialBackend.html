Detailed Description

The device behind a QSerialPort: a USB serial adapter or a device node. The port opens the one that its name calls for and calls it on its own thread.

A function that returns false, or startWrite() that returns -1, has set the port's error, and did so last: the port's owner may close the port in response before the function returns.

◆ startReading()

virtual bool AndroidSerialBackend::startReading ( )
pure virtual

Starts passing the device's input to the port's newDataArrived(), or resumes it after newDataArrived() has answered that the port has no room for more. On that answer the backend reads the device no further, so that the device or the system holds its input back instead of the port dropping it. Once the device is lost it fails without setting the error again.

◆ startWrite()

virtual qint64 AndroidSerialBackend::startWrite ( const char * data,
qint64 maxSize )
pure virtual

Takes up to maxSize bytes to write and returns how many, or -1, without waiting for the device. It reports the bytes to the port's writeCompleted() as they are written, perhaps before it returns, and calls that with 0 when it took fewer than it was offered and can take more. The port offers nothing more until all that was taken is reported.
